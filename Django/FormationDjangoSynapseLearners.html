Partie 1 - Maîtriser les bases de Django

  1. Les concepts fondamentaux de Django

  1. Framework

Django est un framework web back-end Python, open source et gratuit. En une phrase nous avons déjà beaucoup de notions à définir.

Un framework est un cadre de travail, “un ensemble cohérent de composants [...] qui sert à créer les fondations [...] de tout ou partie d'un [projet informatique]”. Pour prendre une image, un framework est un énorme hangar contenant un grand nombre d’outils prêt à l’emploie pour réaliser un type de tâche, dans notre cas un site web, puisque Django est un framework web. Dans le hangar qu’est le framework nous trouverons de nombreux outils qui rendront le développement d’un site web plus rapide et facile, une fois le framework maîtrisé. En effet, certains éléments de la conception d’un site web sont très complexes, comme par exemple la sécurité, le serveur, l’authentification… Django contient déjà ces éléments, et en plus de manière très optimisé, ce qui nous évite de les créer nous même. Pas étonnant que la devise de Django soit : Le framework pour les perfectionnistes qui ont des deadlines.

C’est en 2003 que le développement de Django commence, avec comme langage Python. Django est Open source, ce qui signifie que son code est libre d’utilisation et est produit par une communauté de développeurs sous la direction de la Django Software Foundation. Il est en plus gratuit, ce qui fait que vous n’avez rien à débourser pour l’utiliser, si ce n’est un ordinateur.

De nombreux sites à succès utilisent Django, parmi lesquels Instagram, Pinterest et National Geographic, pour ne citer que ceux-là.

Le site officiel de Django donne de solides raisons de l’utiliser. C’est sans aucun doute le meilleur framework Python pour le web !

  1. MVT

Un framework impose un cadre de travail, une manière de programmer, qui se caractérise souvent par une architecture. On appelle cela un design pattern. Celui de Django se nomme MVT, ou Modèle-Vue-Template.

Le Modèle correspond aux données, stockées généralement dans une base de données. Dans Django, le modèle se trouve dans un fichier models.py.

Le Template correspond aux pages HTML, qui contiennent ce que l’utilisateur verra sur son navigateur.

La Vue correspond à la logique du programme, l’élément qui va adapter le template en fonction de ce qui se trouve dans la base de données. Dans le fichier views.py, la ou les vues auront la forme de fonctions qui prendront en paramètre une requête http. C’est la vue qui autorisera ou non l’accès à une page pour les utilisateurs connectés, ou encore l’affichage du nom de l’utilisateur en récupérant cette information depuis la base de données. On retrouve la vue dans un fichier views.py.

Le cadre de travail est aussi utile pour nous obliger à coder proprement. En effet, il n'est pas possible de mettre la création d’un modèle dans un fichier Vue par exemple, sinon Django nous le fera savoir par un message d’erreur. Notre code devra donc rester propre pour ne pas que Django affiche des messages d’erreurs.

En résumé, une requête HTTP d’un client arrive au serveur Django. Elle prend la forme d’un utilisateur qui veut accéder à une certaine url. Django commence par regarder dans le fichier urls.py à quelle vue cette url est associée. Une fois trouvé, il lance la fonction de la vue, qui va chercher le template à afficher. Avant de l’afficher la vue ajoute les éléments nécessaire contenu dans la base de données, et vérifie au passage le profil de l’utilisateur (est-il connecté ou non ? Etc).

  1. ORM

Pour comprendre le concept d’ORM faisons un petit rappel sur le fonctionnement des bases de données.

Une base de données contient des tables. Chaque table contient une ou plusieurs colonnes.

Chaque colonne a un type précis. On ne peut y insérer autre chose que ce type.

On met en relation les tables ensembles et on y associe des cardinalités.

Le concept de cardinalité consiste en la détermination du nombre minimum (0 ou 1) et maximum (1 ou N) d’élément d’une table A lié à une table B, et inversement. Par exemple, la cardinalité entre une table élève et une table cours sera de 1 à 1 pour l’élève (car un élève suit un cours minimum et un cours maximum à la fois) et de 1 à n (plusieurs) pour le cours (car un cours est suivi par 1 élève minimum et plusieurs élèves maximum). Donc la relation qui lie les deux tables est 1,N (on prend les valeurs maximum de chaque cardinalité).

Sur cette base, on applique les règles de conception suivante en fonction des cardinalités :

  • 1 à 1 : On ne fait rien, les tables sont indépendantes
  • 1 à N : On met la clé primaire de la table qui contient un N dans l’autre table.
  • N à N : On crée une table intermédiaire, qui contient les clés primaires des deux tables.

Pour construire une base de données et définir les relations entre les tables on utilise la modélisation MCD (Modèle conceptuel de données).

Ce qui est souligné correspond à la colonne appelée clé primaire. Il s’agit le plus souvent d’une numération automatique (auto-incrémentée) dans laquelle chaque valeur est unique, pour permettre de cibler une ligne précise. Une table qui contient la clé primaire d’une autre table possède ce qu’on appelle une clé étrangère.

La manipulation des données d’une base de données passent par un Système de Gestion de Base de Données Relationnelles (SGBDR) ou NoSQL. Il s’agit de logiciels qui vont nous permettre de stocker et manipuler de l’information. On peut citer parmi les plus connus MySQL, PostgreSQL, Oracle et Microsoft SQL Server. Et comme vous le savez sûrement, il faut utiliser le langage SQL (Structured Query Language) pour interagir avec un SGBDR. C’est là que l’Object Relational Mapping (ORM) de Django entre en jeu. Il s’agit d’une technique qui nous permet de coder en Python et de laisser à Django le soin d’écrire le code SQL pour nous, c’est-à-dire les quatres opérations fondamentales des bases de données : CRUD :

  • Create (Création) : Insérer des données dans la base de données
  • Read (Lecture) : Lecture de données, le plus souvent pour affichage
  • Update (Mise à jour) : Mise à jour de la valeur des données
  • Delete (Supprimer) : Suppression de données devenus inutiles

Pas besoin d’apprendre un autre langage de programmation. Néanmoins je vous encourage à vous pencher sur le langage SQL, car c’est un incontournable de l’informatique.

En résumé, Django s'occupe des choses difficiles et rébarbatives pour que vous vous concentriez sur la création de votre site Web. En vous permettant de réutiliser du code prêt à l’emploi, Django vous permet d’appliquer pleinement la méthodologie appelé DRY (Don't Repeat Yourself), et est livré avec des fonctionnalités prêtes à l'emploi telles que le système de connexion, la connexion à la base de données et les opérations CRUD.

  1. Fonctionnement général de Django

Le fonctionnement général de Django est le suivant :

  1. Un utilisateur souhaite consulter une certaine url. Django cherche dans le fichier urls.py pour voir si cette url existe.
  2. Une fois trouvé il cherche la vue correspondant à cette url. La vue va charger le template adéquat, et y ajouter les informations nécessaires, issus de la base de données.
  3. Enfin Django renvoie une nouvelle page HTML à l’utilisateur, contenant tout ce qu’il faut (images, vidéos, texte…). Évidemment celà se passe très vite.

Ce que nous venons de faire s’appelle un queryset. Il s’agit d’un point d'entrée vers l'ORM de Django, une liste d'objets d'un modèle. Il nous permet de manipuler l’ensemble des données de la base de données en utilisant du code Python.

Voici quelques syntaxe utilisent à connaître :

  • Centre.objects.all() : Lister l’ensemble des objets stockés dans le modèle

  • Centre.objects.all()[0].nom : Afficher la valeur du nom de la 1ère occurrence de la table Centre

  • Centre.objects.all().values() : Lister l’ensemble des données de chaque objet de la table

  • Centre.objects.all().order_by('pays').values() : Afficher l’ensemble des données de la table Centre en les triant en ordre alphabétique (et croissant pour un champ numérique)

  • Centre.objects.all().order_by('pays').values() : Afficher l’ensemble des données de la table Centre en les triant en ordre inverse alphabétique (et décroissant pour un champ numérique). Il faut ajouter un - devant le nom du champ à filtrer

  • Centre.objects.all().order_by('pays', 'id').values() : Trie en se basant sur plusieurs champs. D’abord en ordre alphabétique de la colonne pays et ensuite en ordre croissant pour la colonne id

  • Centre.objects.values_list(‘nom’) : Lister l’ensemble des valeurs de la colonne nom de la table Centre         

   

  • Centre.objects.filter(nom='Force center').values() : Lister l’ensemble des valeurs de la ligne qui a pour valeur de la colonne nom “Force center”

  • Centre.objects.filter(nom='Force center', pays=’Vietnam’).values() : Lister l’ensemble des valeurs de la ligne qui a pour valeur de la colonne nom “Force center” ET pour valeur de la colonne pays ‘Vietnam’

  • Centre.objects.filter(pays="France").values() | Centre.objects.filter(pays="Thailande").values() : Lister l’ensemble des valeurs de la ou des lignes qui ont pour valeur de la colonne pays “Vietnam” OU ‘Thailande’. Pour une condition ET il faut remplacer le | par un &.

  • Une autre façon d’écrire la même chose est d’utiliser la fonction Q du module django.db.models

Il existe de nombreux autres mécanismes associés aux queryset. Vous pouvez en trouvez d’autres à cette adresse : queryset

Utiliser le modèle utilisateur avec Django

La connexion implique un certain nombre de mécanismes. Le principal étant probablement la base de données. En effet, il va falloir stocker les informations de l'utilisateur. Quelles informations ? À minima son nom, prénom, email et mot de passe. Heureusement pour nous, Django nous fournit un modèle prêt à l’emploi appelé User. Ce modèle peut hériter de deux classes :

  • AbstractUser
  • AbstractBaseUser

La classe AbstractUser contient déjà les champs suivants :

  • username  (nom d’utilisateur) :  Il est utilisé par défaut pour se connecter, mais on peut changer cette option
  • first_name  (prénom)
  • last_name  (nom de famille)
  • email
  • password  (mot de passe) : Lors de leurs stockages, les mots de passe sont hachés dans la base de données. Cela signifie que Django y applique une fonction de cryptographique pour sécuriser le mot de passe. En effet, il ne faut jamais sauvegarder un mot de passe en clair.
  • is_staff  (est un membre du personnel) : Cette valeur est un booléen qui, s'il vaut True, permet à un utilisateur de se connecter au site administrateur Django.
  • is_active  (est actif) : Cette valeur est un booléen. Il est en général préférable de la mettre à False pour signaler qu’un utilisateur est inactif  plutôt que de les supprimer, ce qui peut engendrer des incohérences dans la base de données.
  • is_superuser (est un superutilisateur) : Cette valeur est un booléen qui permet à celui pour qui il vaut True d’obtenir automatiquement tous les droits.

Il est tout à fait possible d’ajouter des champs à ce modèle de base, et de simplement ignorer les champs dont vous  n’avez pas besoin. Dans le cas où vous souhaitez vraiment enlever certains champs il est préférable d’utiliser la classe AbstractBaseUser qui elle ne contient qu’un seul champ par défaut, password. Le reste vous devrez l’ajouter. La documentation de Django vous donnera davantage de précisions sur cette classe à cette adresse : https://docs.djangoproject.com/fr/3.2/topics/auth/customizing/#specifying-a-custom-user-model

Dans notre cas nous allons utiliser la classe AbstractUser. En effet, en général, il est préférable de construire son modèle User à partir de la classe AbstractUser pour une meilleure compatibilité et une intégration plus naturelle avec Djago.
